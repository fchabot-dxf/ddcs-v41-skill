# DDCS V4.1 — screens and keys

> Every measured statement names the bench test that measured it (see evidence.md).

## Measured on this controller

- Param page edits are saved ONLY when the page is left with Main... (F7); Esc or Logout discards them without a word. *(#324 change, settings file watched)*
- A USB keyboard works: arrows jog, numpad Enter = Start (with NumLock ON; with NumLock OFF it turns the SPINDLE on: v41-kbd-numpad-enter), Pause = Pause, numpad 0 = Reset, Tab = file manager; Esc does nothing outside a dialog. *(owner keyboard test)*
- Print Screen saves the screen to /local/BMP<n>.bmp (1024x600, 16-bit). The counter restarts at BMP0 each boot and OVERWRITES the old BMP0.bmp: copy screenshots off before a power-cycle. *(owner Print Screen test)*
- numpad Enter = Start only with NumLock ON. With NumLock OFF it turns the SPINDLE ON (M3, S 24000) and does NOT start the program. Plain Enter does not start a program. A keyboard or a script must know the NumLock state before it sends Start. *(bench keyboard sweep, NumLock off and on (twice))*
- ⛔ Backspace = GO TO ZERO: one tap drove all three axes to work zero at about F5000 (the status bar read GOTOZERO... / BUSY). Esc does not stop it; F3 (Reset) does. On a live machine a stray Backspace is an unconfirmed rapid to X0 Y0 Z0. *(bench keyboard sweep; F3 half a second after Backspace)*
- ⛔ F6 = SPINDLE on/off: the first press sets M3 and S 24000, the second sets M5. On a real machine a stray F6 STARTS THE SPINDLE. *(bench keyboard sweep (F6 twice))*
- ⛔ The numpad is a jog pad (CONT mode, one tap each, pairs returned the readout exactly): 6 / 4 = X+ / X-, 8 / 2 = Y+ / Y-, 9 / 3 = Z+ / Z-; the arrows jog X and Y, PgUp / PgDn jog Z. On a real machine every numpad digit but 5 moves an axis. *(bench keyboard sweep (jog pairs))*
- F1-F7 are the seven soft keys under the screen, in order (Start, Pause, Reset, View, MpgGuide, Spindle, File): their meaning follows the page. F7 cycles the pages Main, File (the file manager), Param, Main. F4 = View, the I/O monitor (the first press after a page change is swallowed). *(bench keyboard sweep (F1-F7 and the I/O monitor))*
- F3 = Reset is a TOGGLE: the status box turns red RESET and F3 again clears it (Esc does not). It also stops a move under way. While the box is red RESET, Start is ignored. *(bench keyboard sweep (F3 twice) and the first bench-runner batch)*
- numpad / and F10 toggle the jog mode CONT / STEP (STEP opens an Input Dialog "Jogging distance"); F5 toggles the jog-mode highlight. *(bench keyboard sweep (numpad /, F10, F5))*
- ⛔ On the Main page a USB keyboard HOLD does what a tap does not for some keys: numpad * held about 2 s = ZERO Z and numpad 5 held about 2 s = ZERO XY. It silently rewrites the work zero (Abs Z or Abs X and Y go to 0.000 at the current position, the G54 offset changes); a tap does nothing visible. The vendor keyboard chart says to hold these keys over 3 seconds (it is for software 2022-11-02 or earlier); on 2025-04-04 about 2 s was enough, because the hold is the first kernel key repeat, not a timer. In Mode 2 (NumLock) the chart names numpad * = Zero A, 7 = Home and 3 = Fix Probe the same way (not tried here). Numpad - and + held also ramp the jog speed JSR by 5 % per repeat (100 % down to 0 % and 0 up to 110 % in 2 s: JSR is not capped at 100 %). So a program, a script or a held key on a USB keyboard can change the work zero or the speeds without a dialog. Put back by writing the work position variables (#1506 X, #1507 Y, #1508 Z, as the vendor zeroxy.nc and zeroz.nc do) to the old values, and the JSR with + and - taps. *(a bench script: numpad * and 5 holds, AUDIT_WCS_RESTORE put the zero back; t3941)*
- Cancel depends on the dialog kind: Esc cancels an Input Dialog (the "Jogging distance" box; PgUp does not). PgUp, the panel's Z-up key, cancels a Message box such as the boot "Go to home?" (Esc, Tab, the arrows and the numpad do nothing to it). *(bench keyboard sweep (Jogging distance and the boot box))*
- The File page ignores the first TWO keys after it opens: Esc returned to the Main page only on the third press, 20 of 20 times (with or without another key first), while Tab into the File page registered 20 of 20. It is deterministic, not a random miss. Print Screen writes no screenshot on the File page. *(key_miss2 (20 cycles, the dongle, judged by webcam), 2026-10-29)*
- Ctrl+Alt+Del from a USB keyboard reboots the V4.1 without powering it down, and it recovers a FROZEN V4.1 (the nested-comment freeze): measured 2 reboots from READY and 2 of 2 freeze recoveries. The SMB port goes away about 3 s after the chord, the shares are back in 27-33 s, Print Screen answers in 35-95 s (the first attempts may fail while the boot finishes), and the boot "Go to home?" box is up (PgUp cancels it). The chord must be real: Ctrl and Alt held, then Delete. Measured only on the nested-comment freeze: the other freezes (#3000, a jump without Macro Mode, the 14-word M98, an in-place overwrite) were not retried with it. A reboot lost nothing the bench showed: the selected job and the DRO positions were the same afterwards (the bench is never homed, so a homed state is unobserved); it only brings back the boot "Go to home?" box. Use it before the power plug. *(a bench script chord / freeze (t3933))*
- Every dialog Ok on the V4.1 is a LONG press: on the panel the Z- (ENTER) key held about 1 s (a tap does nothing). A USB numpad-Enter (or Enter) HOLD is Ok on every dialog tested (MarcoDialog, Advanced Startup and the Simulation dialog), from the dongle and from a real keyboard; a TAP is not. How long, per dialog: a MarcoDialog took a 1.5 s hold 2 of 2 and a 1.8 s hold 4 of 5, the fifth HALTING the run (status RESET at the line after the dialog, cause not shown); Advanced Startup took 1.5 s and 2 s holds; the Simulation dialog took a 2 s hold 3 of 3 (1.5 s there is not measured). Hold about 1.5 s on a MarcoDialog, about 2 s on the Simulation dialog. The dongle and a real keyboard look identical to the controller (the same key-down, a repeat about 245 ms later, then one every 40 ms: evdev log, t3935). The hold must be a real one (the dongle's hold command, or a tap with a hold time): a plain tap does nothing. In a dialog PgDn is the RIGHT arrow (it moves the selection). A program that opens a dialog therefore needs a held Enter: an operator (Enter or the panel's ENTER), or a USB device that sends a real hold. *(the Simulation dialog, MarcoDialog and Advanced Startup walks (owner, dongle holds, real keyboard); evdev_log run 2; t3936; AUDIT_DLG_HOLD (a bench script, 7 runs); AUDIT_SEQ_P8001, AUDIT_SEQ_P8001_M0)*
- No USB key opens the Main page menu (Goto zero, Zero, Home, Probe, Advanced machining, Bias, Breakpoint, Coordinate origin, Centers, Simulation): the panel Shift key is a panel code from the motion device, not a USB event, so keyboard Shift, F8, numpad 7 and every other key do nothing there (Pr313 = 1 (Menu Mode) here; 0 = 2nd function). NumLock switches the keyboard between Mode 1 and Mode 2 on the Main page only. The menu items' dialogs can be opened by a program instead (v41-dialog-vendor-from-program). Measured again on 2026-10-24 with real holds: top-row digits, Esc, Tab, Enter, F2-F5, F7-F12, numpad / and numpad 5 and 6 (Mode 1 and Mode 2), and Ctrl, Shift and Alt with F2-F12, Esc, Home and Application, each tapped and held 2 s, opened no menu (a modifier is ignored on the Main page); numpad / and F10 held 1, 2 and 3 s only toggle CONT / STEP, so the vendor chart label Mode Shift on numpad / is the panel key picture, not a USB hold. No soft key on the Main, File, Edit or Param pages is a menu, Shift, Advanced Machining or Sequence key. *(the firmware key tables (keymap-firmware.json) and the bench: the owner's panel Shift, the dongle sweep, a bench script and the UI map (t3941))*
- A USB mouse does nothing on the V4.1: no pointer is drawn, and a click (or a held then released button) on 6 main-screen targets (the View and File... soft keys, the program-path box, the FRO field, a blank area, the far corner) and on Cancel of the boot "Go to home?" box changed no pixel. *(the t3885 native-pointer test (a USB mouse, no daemon, pixel diff))*
- A keyboard Start sent right after another key can be lost: Print Screen immediately before Space + numpad Enter (a 0.4 s gap) started nothing; with no key just before and a 1 s gap after Space, numpad Enter started the program (observed twice). *(the t3885 blit and cursor-daemon launches (dongle))*
- A USB HID keyboard emulated by an ESP32-S3 (TinyUSB device mode, which uses the S3's native USB port; a keyboard-only device, no USB serial interface) is accepted by the V4.1 as a keyboard, hot-plugged into its USB port, alongside a real keyboard (two keyboards work). It is not usable at once: the device reported itself enumerated about 2 min after the plug-in, and about 1 min after a controller reboot; whether that delay is the controller's or the device's is not measured. A build that added a USB serial interface to the keyboard (a composite device) was neither shown to work nor to fail. To the controller its keys are a real keyboard's (v41-kbd-ok-long-press), with the same conditions and hazards: Start is numpad Enter with NumLock ON only, and with NumLock OFF the same key starts the spindle (v41-kbd-numpad-enter); Backspace drives all three axes to work zero (v41-kbd-backspace); a dialog Ok is a held Enter, about 1.5 s on a MarcoDialog and about 2 s on the Simulation dialog (v41-kbd-ok-long-press). *(the bench keyboard device: hot-plug next to a real keyboard, its enumeration status, a Print Screen from it (t3623); its re-enumeration after a controller reboot)*
